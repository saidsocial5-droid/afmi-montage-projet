# دليل النشر والتحديث عبر GitHub

**القرار المعماري:** ADR 26 في `docs/DECISIONS.md`

## كيف يعمل النظام

1. ترفع الشيفرة إلى مستودع GitHub، ثم ترسل وسماً (tag) برقم الإصدار، مثل `v1.9.20`.
2. يتولى GitHub Actions الباقي تلقائياً عبر الملف `.github/workflows/release.yml`:
   - يتحقق من تطابق أرقام الإصدار.
   - يشغّل الاختبارات.
   - يبني البرنامج.
   - ينشئ ملف التثبيت `AFMIMontageProjet_Setup_v1.9.20.exe`.
   - يحسب بصمته SHA-256.
   - ينشره في صفحة **Releases** بالمستودع.
3. عند تشغيل البرنامج على أي حاسوب مثبَّت، يجد الإصدار الجديد ويُحدِّث نفسه تلقائياً (ADR 29):
   - يحمّل ملف التثبيت في الخلفية، و**يتحقق من بصمته**. إن لم تطابق البصمة المنشورة يُلغى التحديث.
   - يُعلم المستخدم بأن الإصدار جاهز، ويقترح التثبيت فوراً.
   - إن لم يختر التثبيت فوراً، يُثبَّت الإصدار بصمت **عند إغلاق البرنامج**، دون مقاطعة العمل.
   - المشاريع والإعدادات لا تُمس.
   - يمكن إيقاف التثبيت التلقائي من **Paramètres › Mises à jour**؛ عندها تُعرض نافذة «تحديث متاح» عند كل إصدار جديد.

## الإعداد (مرة واحدة)

1. أنشئ المستودع `afmi-montage-projet` في حساب `saidsocial5-droid` على https://github.com/new:
   - النوع: **خاص (Private)**.
   - دون README أو أي ملف آخر.
2. أنشئ مفتاح وصول للقراءة فقط، تحتاجه الحواسيب لتحميل التحديثات من مستودع خاص:
   - افتح https://github.com/settings/personal-access-tokens/new (Fine-grained token).
   - **Repository access:** اختر Only select repositories ثم `afmi-montage-projet`.
   - **Permissions › Repository permissions › Contents:** اختر **Read-only**، ولا تمنح أي صلاحية أخرى.
   - **Expiration:** يُنصح بسنة، وجدّده قبل انتهائه.
   - انسخ المفتاح الذي يبدأ بـ `github_pat_`.
3. في كل حاسوب، يُدخل هذا المفتاح مرة واحدة. منذ الإصدار 1.9.23 يطلبه البرنامج بنفسه عند التشغيل إن كان ناقصاً أو مرفوضاً (نافذة «Activer les mises à jour automatiques»)، ويتحقق منه فوراً. ويمكن إدخاله أيضاً، لأي مستخدم، في **Paramètres › Mises à jour › Clé d'accès**:
   - يُحفظ المفتاح مشفراً على ذلك الحاسوب فقط.
   - لا يُرسل إلى الفريق، ولا يُدمج في ملف التثبيت.
   - لا يُرسل إلا إلى `api.github.com`.
   - هذا المفتاح يسمح بقراءة الشيفرة. إن ضاع حاسوب، احذف المفتاح من GitHub وأنشئ غيره.
4. ارفع الشيفرة والإصدار الأول. المستودع المحلي جاهز: الفرع `main` والوسم `v1.9.20` والوجهة `origin`.
   ```powershell
   git push -u origin main --tags
   ```
   - الملف `.gitignore` يستبعد مجلدات البناء والشهادات والملفات الثنائية الكبيرة.
   - تابع التنفيذ في تبويب **Actions**. بعد نحو 15 دقيقة يظهر الإصدار في **Releases**.
   - المستودع الخاص المجاني يمنح 2000 دقيقة تنفيذ شهرياً، وكل دقيقة على Windows تُحتسب دقيقتين. هذا يكفي لعشرات الإصدارات في الشهر.

## نشر إصدار جديد لاحقاً

1. غيّر رقم الإصدار في مكانين **بالرقم نفسه**:
   - `AFMI Montage projet 2.csproj` ← `<Version>1.9.21</Version>`
   - `setup.iss` ← `#define MyAppVersion "1.9.21"`
2. نفّذ:
   ```powershell
   git commit -am "Version 1.9.21"
   git push
   git tag v1.9.21
   git push origin v1.9.21
   ```

## ملاحظات

- **اسم المستودع:** النسخ المبنية عبر GitHub Actions، ونسخة 1.9.20 المحلية بعد إعادة بنائها، تعرف مستودعها تلقائياً (`saidsocial5-droid/afmi-montage-projet`). أما النسخ الأقدم فيُدخل المدير اسم المستودع يدوياً في الإعدادات.
- **تحميل ملف التثبيت يدوياً:** في المستودع الخاص يتطلب ذلك تسجيل الدخول إلى GitHub. لذلك يوزَّع أول تثبيت باليد (USB أو Drive)، وتأتي التحديثات اللاحقة تلقائياً.
- **البناء المحلي:** يمكنك البناء على جهازك بالأمر:
  ```powershell
  .\build_and_sign.ps1 -GitHubRepository الحساب/afmi-montage-projet
  ```
  ثم ترفع يدوياً الملفين `.exe` و`.exe.sha256` من مجلد `Installer` إلى Release جديد. **ملف البصمة إلزامي**، وبدونه يرفض البرنامج التحديث.
- **ملف التثبيت غير موقَّع رقمياً.** لذلك قد يظهر تحذير Windows SmartScreen عند أول تثبيت: «Informations complémentaires» ثم «Exécuter quand même». لإزالة التحذير تحتاج شهادة توقيع شيفرة (Code Signing)، تُمرَّر إلى `build_and_sign.ps1`.
- **عدد مرات الفحص:** يفحص البرنامج التحديثات مرة واحدة عند كل تشغيل. يمكن الفحص يدوياً من **Paramètres › Mises à jour › Rechercher une mise à jour**.
